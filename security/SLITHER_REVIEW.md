# Slither Review

## Gate and execution

- Analyzer: `slither-analyzer` 0.11.5 with Solidity 0.8.28.
- Compilation: direct standard-JSON `solc` compilation with the Cancun EVM target and the OpenZeppelin remapping. This avoids relying on the legacy Hardhat build-info shape that Slither's Hardhat frontend expects and is compatible with this Hardhat 3 project.
- CI policy: dependency and test-mock paths are filtered, the JSON report is retained as a CI artifact, and any high-severity finding fails the job.
- Last local result: completed with no high-severity finding.

## Reviewed project findings

| Detector                            | Location                                                 | Review and disposition                                                                                                                                                                                                                                                                                                                       |
| ----------------------------------- | -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `reentrancy-no-eth`                 | `Marketplace.buyCopy`, `Marketplace.buyExclusive`        | Reviewed false positive for the selected guard implementation. Both entrypoints use OpenZeppelin `ReentrancyGuardTransient.nonReentrant`; the malicious callback-token acceptance test confirms a callback cannot complete a second purchase. State and payment changes also revert atomically on downstream failure.                        |
| `reentrancy-events`                 | `Marketplace._list`, `DatasetRegistry.resolveChallenge`  | Reviewed. External calls are limited to protocol contracts configured at construction or through one-time ADMIN wiring. Any failure reverts the whole transaction. The challenge path writes its terminal state before calling the Marketplace; listing state is finalized around the trusted registry transition and is covered end-to-end. |
| `timestamp`                         | challenge/listing purchase boundaries and timelock tests | Intentional use of block time. The protocol defines challenge eligibility and governance delay in seconds; exact-deadline behavior is explicitly tested. No timestamp is used as randomness.                                                                                                                                                 |
| `unused-return`                     | `RevenueSplitter` Dataset existence check                | Intentional. `getDataset(datasetId)` is called for its required unknown-Dataset revert; the returned struct is not needed by accrual accounting.                                                                                                                                                                                             |
| `cyclomatic-complexity`             | `Marketplace._list`                                      | Reviewed. The branches enforce the two sale kinds, contributor authorization, Dataset lifecycle, challenge state, and zero-copy exclusivity in one atomic listing transition. Policy branches have dedicated acceptance tests.                                                                                                               |
| `naming-convention`, `unused-state` | upgrade storage gaps and constant interface getters      | OpenZeppelin-compatible `__gap` fields are deliberately reserved for future storage-layout-safe upgrades. `WEIGHTS_MANIFEST_VERSION`, `CHALLENGE_EVIDENCE_VERSION`, and `CHALLENGE_RESOLUTION_SLA` are public Solidity constants, so their generated interface getter names intentionally retain constant-style uppercase naming.            |
| `unimplemented-functions`           | inherited ERC-1155 views                                 | Inheritance-analysis false positive. `EntitlementNFT` inherits the ERC-1155 implementations and overrides only the transfer update hook required for Copy non-transferability. Compilation and ERC-1155 behavior tests pass.                                                                                                                 |

These dispositions are limited to the current source revision. A new Slither result must be reviewed again rather than assumed to have the same causes.
